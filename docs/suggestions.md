# Suggestions

## 🔴 Vulnerabilities

- **2026-09-28 — THE APP HAD NO AUTHENTICATION AT ALL. Every one of the 18 `/api/*` routes and every page was world-readable and world-writable.** Anyone could list the library, read any document, rewrite it, restore any version, delete it, read the global system prompt, rewrite the design tokens, and spend the deployment's DeepSeek and PDF-render budget. Fixed with passwordless email-OTP auth (`lib/auth.ts` + `lib/user.ts` + `lib/api-auth.ts` + `middleware.ts`): 6-digit codes from a CSPRNG stored only as SHA-256 (salted with the address), 10-minute expiry, 5 attempts then the row is destroyed, 3/email/10min + 10/IP/10min rate limits, and 32-byte opaque session tokens (the server stores only `sha256(token)`, the browser gets an httpOnly `SameSite=Lax` cookie). `middleware.ts` gates every page and every `/api/*` except `/api/auth/*`, `/_next` and static files, and **fails closed** — any error is a 401, API paths get a JSON 401 and pages redirect to `/login`. No JWT and no new dependency: Node's `crypto` covers it. **Still open / follow-ups:** instructions remain app-wide (one design system) and are gated by authentication rather than partitioned per account; there is no CSRF token (the cookie is `SameSite=Lax`, which is sufficient for the JSON `Content-Type` API surface but a real CSRF token is the belt-and-braces answer if a cookie-authenticated cross-site form ever appears); there is no email-domain allow-list or rate limit across IPs sharing a NAT, and the in-memory limiter is per-instance on serverless (the database rules — one live code per address, 5 attempts — are what actually bound the abuse).

- **2026-09-28 — IDOR: every document/folder/version/file lookup ignored ownership.** `GET /api/documents/[id]` used `findOne({_id: id})`, `lib/storage-mongo.ts` used `deleteOne({_id: id})`, `PATCH /api/folders/[id]` used `findOneAndUpdate({_id: id})` — so any caller could read, rewrite, restore versions of, and delete **any** document or folder in the deployment. The `ownerId` seam had been declared in `lib/storage.ts` since FR-45 and never once populated. It is now a REQUIRED argument on every document/folder/version/file operation, always derived from the verified session by `requireOwner()`; the owner id is never read from a body, query or header, and a foreign document answers **404 (not 403)** so existence is never confirmed. Defense in depth: the routes re-authorize even though middleware already gated the request, and the natural keys are now database-enforced with unique indexes (`{ownerId, id}` on documents, `{ownerId, docId, version}` on docversions, `{email}` on users).

- **2026-09-28 — `DELETE /api/documents/%2A` wiped the ENTIRE file index (and targeted every Blob in the store).** `lib/storage-mongo.ts` interpolated the unescaped route id into a Mongo regex — `find({_id: {$regex: `^${id}/`}})`. An id of `*` matches every row, so the following `deleteMany` destroyed every file-index row and `del(urls)` targeted every blob. Replaced with an exact prefix RANGE (`{_id: {$gte: `${id}/`, $lt: `${id}0`}}`, exported as `filePrefixRange()` and unit-tested), plus early id validation (`/^[A-Za-z0-9_-]{1,64}$/` → 400) on every `[id]` route and a `DOCUMENT_ID_PATTERN` guard inside the FS backend's `docDir()` (which was a `path.join` on an unvalidated id — a traversal primitive).

- **2026-09-28 — `POST /api/documents` silently overwrote (and snapshotted) other people's documents.** `app/api/documents/route.ts` did `replaceOne({_id: doc.id}, {...doc}, {upsert: true})` with no existence check, so a POST carrying an existing id rewrote that document with attacker-supplied content. POST is now a CREATE: 409 on an existing id, and the stored row is built server-side with a fresh `crypto.randomUUID()`, the session's `ownerId` and server timestamps. `ownerId` / `createdAt` / `instructionsSnapshot` / `sourceHtml` / `opensInPractice` are server-owned on every write (PUT keeps the stored values rather than accepting a client's).

- **2026-09-28 — Design-token CSS injection → stored XSS.** An anonymous `PUT /api/instructions` accepted unbounded content that became BOTH the global system prompt AND the design tokens, and `lib/html-template.ts:buildCss` interpolated 34 token values raw into the CSS inside `<style>`. A value like `#000 } </style><script>fetch('/api/documents')</script>` closed the style block and produced executable HTML, served from the app's own origin by `GET /api/documents/[id]/html` and downloadable via "Download HTML". Two independent layers now: `parseTokensBlock` validates every value against `/^[#a-zA-Z0-9(),.%\-_ ]{1,64}$/` (falling back to the default on mismatch) and caps the token count at 128, and `buildCss` routes the whole token tree through `safeTokenValue()` which strips `<`, `>`, `{`, `}` and backslashes.

- **2026-09-28 — Stored XSS through pasted HTML.** `validateAndWrapHtml` only stripped code fences, so imported `<script>`, `on*` handlers, `<base>`, meta-refresh and `javascript:` hrefs were stored verbatim and served as `text/html` from the app origin. New `lib/sanitize.ts` scrubs on ingest (drops `<script>/<style>/<iframe>/<object>/<embed>/<applet>/<frameset>/<noscript>/<template>/<svg>/<math>` with their content, the `<base>/<link>/<meta>/<frame>` tags, `<form>` wrappers, comments, every `on*` attribute, `srcdoc`, and any URL attribute whose scheme is not http/https/mailto/tel/ftp — including entity- and whitespace-obfuscated `java&#9;script:` — and strips `style` attributes that reach outside inline CSS). The wrapper's `<title>` is now escaped too. Second layer: the HTML response carries `Content-Security-Policy: default-src 'none'; style-src 'unsafe-inline'; img-src data:` and `X-Content-Type-Options: nosniff`. The sanitizer is dependency-light and regex-based **on purpose** — it is covered by 25+ negative tests in `tests/smoke-m10.ts` (including the UNCLOSED `<script>` case that a `[\s\S]*?</script>` scrub misses entirely), and the CSP is what makes a miss non-exploitable.

- **2026-09-28 — Unauthenticated, unbounded, unthrottled resource exhaustion.** `GET /api/documents/backup` listed EVERY document in the deployment, rendered a full PDF for each and buffered the whole ZIP in memory, with no rate limit (and `entries.length` is written as a UInt16, so >65535 entries throws). It is now owner-scoped, rate limited to 2/IP/10min, capped at 50 documents, and pre-checks the 65535 entry ceiling. `lib/ai.ts` had NO fetch timeout (a hung provider held the handler open forever) → `AbortSignal.timeout(60_000)`; `generatePDFBuffer` had none either → `Promise.race` with `PDF_TIMEOUT_MS`. `lib/schemas.ts` gained hard `.max()` ceilings (title 300, block text 50 000, blocks 2 000, html 2 000 000, instructions 200 000, `goal` 2 000 — `buildAIPrompt` injected `goal` verbatim into the AI message) and `middleware.ts` rejects any body over 5 MB.

- **2026-08-13 — react-pdf 4.6.0 (latest) `fixed` + `position: absolute` + `bottom` footer bug.** On continuation pages of multi-page documents, the paginator omits the page box height when splitting (`omit('height', page.box)` in `@react-pdf/layout` `splitPage`), which breaks yoga's bottom resolution and gives the footer a garbage ~1e22pt height → pdfkit rejects the coordinate ("unsupported number: -1.2915355457378698e+22") → the whole PDF download 500s. Only documents long enough to paginate were affected. **Workaround in place** (`lib/pdf.tsx`): pin `height` to one footer line on the footer View. If we ever upgrade react-pdf, re-test a 60+ block document immediately — and consider removing the pinned height if the upstream layout is fixed.

## 🟢 Improvements

- **2026-09-26 — The smoke-m5 "parse: vocab grid rows" check is FIXED (was a real parser bug, not an outdated assertion):** `elementsByClass()` in `lib/html-to-blocks.ts` used stack pop() without reversing children, returning every sibling group back-to-front — vocab rows (and paragraphs, and qa-answer first-match) parsed in reverse document order. Children are now pushed reversed so pop() visits document order. M5 went 37+1-deferred → **38/38**, run-all **8/8**.

- **2026-09-26 — PDF text extractor committed:** `tests/pdf-extract.py` inflates content streams and decodes hex TJ runs (UTF-16BE + WinAnsi) plus literal runs; verified against real react-pdf output (`Hello RÉPONSE_vocab` round-trips incl. accents). Use it to assert PDF text per variant instead of eyeballing stream sizes.

- **2026-09-26 — Legacy blob-artifact cleanup shipped as a runnable script:** `scripts/migrate-legacy-blobs.mjs` (dry-run default, `--apply` to write; self-contained on `mongodb` + `@vercel/blob`, needs `MONGODB_URI`). Migrates `instructions.snapshot.md` → `doc.instructionsSnapshot` and `document.html` → `doc.sourceHtml` (external-html docs), then sweeps orphaned `files` rows + blob objects. Run it against the Atlas DB when convenient.

- **2026-09-26 — Unsaved-changes tab-close alert shipped:** `Editor.tsx` adds a `beforeunload` guard that prompts only while edits are still dirty (saved sessions never nag) — last-resort net behind the existing `visibilitychange`/`pagehide` flush.

- **2026-08-13 — User preferences in the DB (later, gated on accounts).** Four preferences live in localStorage today: `writer-app:theme` (dark/light), `writer-app:autosave` (toggle), `writer-app:add-type` (last chosen block type), `writer-app:copy-selection` (copy dialog checkboxes) — all per-browser. They logically belong in a storage `settings` collection keyed by owner so they follow the user across devices. Not built because there is NO auth yet (FR-45 `ownerId` seams exist but are always null in v1) — a DB settings row can't be tied to anyone without accounts. When users land: add `settings` to the storage interface + both backends (FS `data/settings.json`, Mongo `settings` collection), a GET/PUT `/api/settings` route, and swap the localStorage reads in ThemeToggle/Editor/BlockList/CopyDialog to fetch-on-mount with localStorage as the offline fallback. Audit done 2026-08-13 — these four keys are the ONLY client-side state that never touches the DB.

- **2026-09-26 — Per-document version history shipped:** every `saveDocument` snapshots the pre-save content (capped at 20, oldest pruned; versions cleaned on delete) via new `snapshotDocument`/`listDocumentVersions`/`readDocumentVersion` seams on both backends (FS `versions/*.json`, Mongo `docversions` collection); new `/api/documents/[id]/versions` + `/versions/[version]` (GET read, POST restore — restoring snapshots current first, so restores are undoable); editor History button + `DocHistory` modal with two-step restore. M8 grows 23 → 27.

- **2026-08-13 — Structured analysis points (the full-pipeline variant — NOT built, deliberate; to-do item 2).** The user chose **free-text bullets** for the analysis/breakdown ("it can be just as answer analysis… that also works; points are just easy to understand") — `- ` lines render as a real `<ul class="point-list">` (HTML) / `•`-prefixed lines (PDF), renderer-only, no new data. This entry records the **structured alternative** in case real point data is ever wanted (independent add/remove/reorder of each point). Full-pipeline design:
  1. `analysisPoints?: string[]` on `QaContent`/`ParagraphContent`/`EssayContent` (`lib/types.ts`; `createBlock` factories get `analysisPoints: []`).
  2. `lib/schemas.ts` — `z.array(z.string().trim().min(1).max(500)).optional()` on all three content schemas.
  3. `lib/structuring.ts` — `aiBlockEntrySchema` gains `analysisPoints` on qa/paragraph/essay shapes; `optList` normalization (drop empty strings/empty arrays).
  4. `docs/html_instructions.md` — the ANALYSIS POINTS rule (2026-08-13) upgraded: "output `analysisPoints` as an array, one point per entry".
  5. `lib/prompt.ts` — JSON shapes in the conversion demand + `BLOCK_FORMAT_SPEC` gain `analysisPoints`; `serializeQa`/`serializeBlocksForAI` emit an `ANALYSIS_POINTS: point1; point2` marker (Copy-for-AI round-trips, same pattern as VOCAB/SYNONYMS).
  6. Editor — `ParagraphFields` + `QaBlockForm` gain a "＋ Points" chip revealing a single-column row editor (RowEditor is term/def; a simplified variant or a reused row with an empty term cell).
  7. `lib/html-template.ts` — analysis renders its points as `<ul class="point-list">` (the free-text `- ` pass stays for hand-written bullets).
  8. `lib/pdf.tsx` — points mapped through `bulletText` (joined with `\n`).
  9. `lib/html-to-blocks.ts` — parse-back recovers `<li>` items under `.qa-analyse`/`.p-analyse` into `analysisPoints`.
  10. Tests — smoke-m7 (+ smoke-m5 parse-back) extended; `buildCopyText` prints `- point` lines under `Analyse :`.
  Why not built: ~10 files for marginal benefit — free-text bullets deliver the same rendered output with 3 files (two renderers + instructions). Build this only if the user asks for per-point editing/reordering.

- **2026-09-26 — Test-document naming + flag lifecycle shipped:** the toolbar Practice pill reads "Test" on generator-made documents with a TEST badge next to the title, plus a "Make normal" action clearing `opensInPractice` (persists through the normal save path) — teachers can reuse a test as a regular worksheet.

- **2026-08-13 — PDF QA cards never split mid-question (done).** react-pdf v4.6 has no `breakInside: "avoid"` style; the equivalent is the `wrap={false}` View prop (moves the whole element to the next page instead of splitting it; oversized elements stay put and push future siblings over — `splitNodes` in `@react-pdf/layout`). Applied to each QA card in `lib/pdf.tsx`, mirroring `.qa-block { break-inside: avoid }` in the HTML template. Verified: 84/84 qa blocks un-split (page count 17→18 as cards moved whole). If react-pdf ever adds `breakInside`, consider switching for readability.

- **2026-08-13 — PDF badge digit centering is empirical, not modeled.** The download's badge digit sat ~3pt high; the first fix (`lineHeight: "18pt"`, CSS-style line-height trick) made it worse (~5.25pt high) because react-pdf anchors the glyph baseline differently than browsers. Current fix: unitless `lineHeight: 1.3` (~7.85pt line box, flex-centering pushes the digit to the 9pt center). If a future font change (tokens.fonts.pdf) shifts the baseline, re-measure with a 96dpi pixel check rather than reasoning from font metrics — the font-metric model did not predict the measured offsets.

- **2026-09-28 — The instructions history restore was broken end to end and is fixed.** `lib/storage-mongo.ts:listInstructionsHistory()` returned only `{version, savedAt}`, but `components/InstructionsEditor.tsx` assumed a full `content` on every entry. So every row in the history list read "0 chars", "Preview" replaced the editor textarea with `""` (destroying unsaved edits), and "Restore" PUT `{content: ""}` which zod rejected with a 400. Both backends now return `content` with each entry (the Mongo rows always had it; the FS backend reads the file), the `?? ""` fallbacks are deleted so a future regression is visible, and Preview now asks before overwriting unsaved work.

- **2026-09-28 — `npm test` now exists and the whole suite actually runs (9/9, was 5/8).** `package.json` had no `test` script, so the real harness in `tests/` was never executed by the normal workflow — and when it was run by hand, **3 of 8 suites (M2, M4, M7) crashed with `ENOENT docs/html_instructions.md`** because `lib/tokens.ts` resolves `REPO_INSTRUCTIONS_PATH` from `process.cwd()` (correctly, the way the Next server does) while the runner was launched from `tests/`. The fix is the cause, not the tests: `tests/run-all.ts` now `chdir`s to the repo root before spawning suites, and `npm test` is `cd tests && npx tsc -p tsconfig.json && node build/tests/run-all.js`. **The Atlas verification the previous commit left outstanding is resolved** — the Mongo-only runtime path is now the only path, and it is the one exercised in production; see `docs/to-do.md`.

- **2026-09-28 — Error boundaries added.** There was no `app/error.tsx`, `app/global-error.tsx` or `app/not-found.tsx`, which mattered more than usual because `getStorage()` THROWS when `MONGODB_URI` is missing — so one absent env var turned every page into Next's generic production screen. `app/error.tsx` (client, digest + Try again + a link to the library), `app/global-error.tsx` (root-layout failures, inline styles so it survives a broken stylesheet) and `app/not-found.tsx` (deliberately neutral about whether a 404 is "missing" or "not yours", so it never confirms that another account's document exists).

- **2026-09-28 — Accessibility pass on the editor controls.** `components/Toolbar.tsx` and `components/Block.tsx` labelled the document-title input, both tags inputs, the per-block heading-level select, the instructions textarea and every glyph-only button (↑ ↓ ＋ ✕ ▾) with nothing but `placeholder`/`title` — which screen readers ignore. All of them now have an `aria-label` (plus `aria-expanded` on the conversion-options disclosure and `aria-pressed` on the answer-reveal toggle). `components/InstructionsEditor.tsx` also dropped its two `window.confirm()` calls in favour of the in-app confirm banners the app already uses in `LibraryList`/`Editor`, and its "← Editor" link (pointing at `/`, the dashboard) is now labelled "← Home".

- **2026-09-28 — Misleading error and layout nits fixed while in the same code:** `lib/storage-mongo.ts` `getDb()` said "filesystem storage should be used (remove MONGODB_URI)" — the exact OPPOSITE of `lib/storage.ts`'s correct advice; `PATCH /api/documents/[id]` accepted any `folderId` and produced a dangling reference (it now looks the folder up first and 400s); `DELETE` answered 204 even when nothing was deleted (both `[id]` routes now 404 on a miss); the `[id]` routes resolved `getStorage()` twice per request (hoisted); and `lib/storage-fs.ts` `docDir()` was a `path.join` on an unvalidated id.
